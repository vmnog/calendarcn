`Calendar` puts the pieces together: a [`CalendarProvider`](/docs/components/calendar-core) for the state, a toolbar with the title, view switcher, today and previous/next, and the [Time Grid](/docs/components/time-grid) or [Month View](/docs/components/month-view) below it. It takes every `CalendarProvider` prop, and the CLI copies its source into your project, so change the toolbar or the layout right in `components/calendar.tsx`.

## Usage

```tsx
import { Calendar } from "@/components/calendar";

export function Schedule() {
  return (
    // The calendar fills its parent's height
    <div className="h-[600px]">
      <Calendar defaultEvents={events} />
    </div>
  );
}
```

Events, the view and the date can each be left to the calendar (`defaultEvents`, `defaultView`, `defaultDate`) or controlled (`events` with `onEventsChange`, and so on), the same as on [`CalendarProvider`](/docs/components/calendar-core#calendarprovider):

```tsx
const [events, setEvents] = React.useState(initialEvents);

<Calendar events={events} onEventsChange={setEvents} defaultView="month" />;
```

The view switcher offers day, week and month, 2 to 9 days at a time, and the weekend, declined events and week number settings. The examples use `createSampleEvents()` from `src/lib/sample-events.ts` for their data; pass your own events instead.

## Build your own

`Calendar` is a short file. For a different header, compose the parts yourself: the provider owns the state, your header reads it with `useCalendar()`, and the body renders whichever view the provider is on.

```tsx
import { CalendarProvider, useCalendar } from "@/components/calendar-provider";
import { MonthView } from "@/components/month-view";
import { WeekView } from "@/components/week-view";

export function MyCalendar() {
  return (
    <CalendarProvider defaultEvents={events}>
      <div className="flex h-[600px] flex-col">
        <Header />
        <div className="min-h-0 flex-1">
          <Body />
        </div>
      </div>
    </CalendarProvider>
  );
}

function Header() {
  const { monthName, year, goToToday, goToPrev, goToNext, switchView } =
    useCalendar();
  // Title, today, previous/next and a view switcher
}

function Body() {
  const { view } = useCalendar();
  return view === "month" ? <MonthView /> : <WeekView />;
}
```

## Keyboard & accessibility

Every event is a button you can reach with <Kbd>Tab</Kbd>. The views only handle keys while one of their events has focus, so a calendar embedded in your page never takes over the page's own shortcuts.

| Action                           | Keys                                                                                                                      |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| Next or previous event on screen | <Kbd>Tab</Kbd> / <KbdGroup><Kbd>⇧</Kbd><Kbd>Tab</Kbd></KbdGroup>                                                          |
| Open the event's details         | <Kbd>Enter</Kbd> or <Kbd>Space</Kbd>                                                                                      |
| Close the details                | <Kbd>Esc</Kbd>. Focus goes back to the event.                                                                             |
| Move a day earlier or later      | <KbdGroup><Kbd>Alt</Kbd><Kbd>←</Kbd></KbdGroup> / <KbdGroup><Kbd>Alt</Kbd><Kbd>→</Kbd></KbdGroup>                         |
| Move earlier or later            | <KbdGroup><Kbd>Alt</Kbd><Kbd>↑</Kbd></KbdGroup> / <KbdGroup><Kbd>Alt</Kbd><Kbd>↓</Kbd></KbdGroup>                         |
| Make it end earlier or later     | <KbdGroup><Kbd>Alt</Kbd><Kbd>⇧</Kbd><Kbd>↑</Kbd></KbdGroup> / <KbdGroup><Kbd>Alt</Kbd><Kbd>⇧</Kbd><Kbd>↓</Kbd></KbdGroup> |

- In the day and week views, <Kbd>Alt</Kbd> + <Kbd>↑</Kbd> / <Kbd>↓</Kbd> move a timed event by one `snapMinutes` step and keep it inside the visible hours. In month view they move it a week.
- Moving an event past the visible days moves the view with it, and focus follows the event.
- `CalendarProvider` renders a polite live region (`role="status"`) that announces each move, resize and create, e.g. "Moved Team standup to Tuesday, October 27, 9:15 AM".
- Each event is labelled with its title and time and reports its selection with `aria-pressed`. Day columns and month cells are labelled groups with the full date. Decorative parts (time axis, grid lines, drag previews) are hidden from assistive tech, and off-screen scroll buffers are `inert`.
- With reduced motion turned on, scrolling snaps without the slide animation.

`Calendar` also turns on the single-key [keyboard shortcuts](/docs/keyboard-shortcuts) (<Kbd>T</Kbd>, <Kbd>J</Kbd>/<Kbd>K</Kbd>, <Kbd>D</Kbd>, <Kbd>W</Kbd>, <Kbd>M</Kbd>…). They listen on the whole page, so pass `shortcuts={false}` when several calendars share a page or the keys clash with your app's.

## Theming

The calendar uses your shadcn/ui theme (`--background`, `--foreground`, `--border`, `--muted-foreground`, `--popover`) plus a few tokens of its own, which the CLI adds to your CSS file for light mode (`:root`) and dark mode (`.dark`). Today's date and the current-time line use `--primary`.

| Variable                 | Used for                                                      |
| ------------------------ | ------------------------------------------------------------- |
| `--event-{color}`        | Event text: the title and time of the default content         |
| `--event-{color}-bg`     | Event background                                              |
| `--event-{color}-border` | The bar on an event's left edge, and the color swatches       |
| `--calendar-weekend`     | Background of weekend columns and weekend cells in month view |

`{color}` is one of `red`, `orange`, `yellow`, `green`, `blue`, `purple` and `gray`. Override them to restyle every event of that color:

```css
:root {
  --event-blue: #1d4ed8;
  --event-blue-bg: #dbeafe;
  --event-blue-border: #3b82f6;
}

.dark {
  --event-blue: #93c5fd;
  --event-blue-bg: #1e3a8a;
  --event-blue-border: #3b82f6;
}
```

They're also Tailwind colors (`text-event-blue`, `bg-event-blue-bg`, `bg-event-blue-border`), which is how the [custom content](/docs/components/calendar-core#custom-event-content) example colors its text.
