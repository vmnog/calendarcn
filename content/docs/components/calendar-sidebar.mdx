Calendar Sidebar is the left column of the [live demo](/), modeled on Notion Calendar's: the [Mini Calendar](#mini-calendar), a scheduling row and a "Meet with..." field, the [Calendar List](#calendar-list), "Add calendar account" when you pass `onAddCalendarAccount`, and a footer with the [Theme Toggle](#theme-toggle). On wide screens it's a fixed column that pushes the page over; on phones it opens as a sheet from the left ([Sidebar Overlay](#sidebar-overlay)).

It reads the date, view and calendars from the surrounding [`CalendarProvider`](/docs/components/calendar-core), so the mini calendar follows the calendar as it moves, numbers its weeks while the provider's week numbers are on, and picking a day goes there (with weekends hidden, a Saturday or Sunday opens the Monday after it in day view). The "Meet with..." field meets with the provider's `contacts` (see [Meeting with people](#meeting-with-people)). Inside a [`SchedulingProvider`](/docs/guides/share-your-availability), the Scheduling row starts marking open times to share, or opens a menu of scheduling links when your app creates them; without one, the row isn't there. "Add calendar account" calls your `onAddCalendarAccount`, to connect an account your way; the live demo adds an .ics file as a calendar. The file is yours, so wire them up there.

## Usage

The sidebar is built from shadcn/ui's sidebar parts, so it needs a `SidebarProvider` around it, inside the `CalendarProvider`. Put it first in the provider's row, with the calendar beside it:

```tsx
import { CalendarProvider } from "@/components/calendar-provider";
import { CalendarSidebar } from "@/components/calendar-sidebar";
import { SidebarProvider } from "@/components/ui/sidebar";
import { WeekView } from "@/components/week-view";

export function CalendarPage() {
  return (
    <CalendarProvider defaultEvents={events} calendars={calendars}>
      <SidebarProvider className="h-screen">
        <CalendarSidebar />
        <div className="flex min-w-0 flex-1 flex-col">
          <WeekView />
        </div>
      </SidebarProvider>
    </CalendarProvider>
  );
}
```

The sidebar owns no open state: pass `open` to show or hide it. On phones, pass `overlay` and close the sheet from `onOpenChange`, which it calls on an outside tap, <Kbd>Esc</Kbd>, its close button and after a day is picked. The demo keeps one state per layout, so the overlay doesn't pop open when the window narrows:

```tsx
function Sidebar() {
  const { isMobile } = useSidebar();
  const [open, setOpen] = React.useState(true);
  const [overlayOpen, setOverlayOpen] = React.useState(false);

  return (
    <CalendarSidebar
      open={isMobile ? overlayOpen : open}
      onOpenChange={setOverlayOpen}
      overlay={isMobile}
    />
  );
}
```

Add your own buttons to the footer, before the theme toggle, with `footerActions`. The demo puts its docs and GitHub links there:

```tsx
<CalendarSidebar
  footerActions={
    <Button variant="ghost" size="icon" className="size-7" asChild>
      <a href="/help">
        <CircleHelpIcon />
        <span className="sr-only">Help</span>
      </a>
    </Button>
  }
/>
```

### Hiding calendars

The list's eye buttons hide and show calendars. Hiding only dims the row; to take a calendar's events off the views, give the provider only the shown events and merge its changes back into your full list. `filterShownEvents()` and `mergeShownEvents()` from `@/lib/event-utils` do both, and [Calendar App](/docs/components/calendar-app) does this for you. [Hide a calendar's events](#hide-a-calendars-events) is a live example.

### Meeting with people

The "Meet with..." field picks people from the provider's `contacts`, as Notion Calendar's does: focusing it lists the recent ones, typing lists the matches (or the typed address), the arrow keys move through them and <Kbd>Enter</Kbd> or a click picks one. <Kbd>Esc</Kbd> closes the list and clears the field. While you type, F, P and the calendar's other keys type into the field.

Picking someone adds them to a "Meeting participants" section under the field: their events show beside yours in the day and week views and the times you're all free are highlighted ([Meeting with people](/docs/components/calendar-core#meeting-with-people)). Hover a row to stop meeting with that person, or press "Clear" to stop meeting with everyone. Teammates added with "Show teammate calendar..." ([People Picker](/docs/guides/meet-with-people)) are listed under "Team calendars", each with a button to remove them. Both lists live in the provider, through [`useCalendarPeople()`](/docs/components/calendar-core#usecalendarpeople), so the sidebar takes no props for them.

### Colors

The sidebars bring Notion Calendar's colors as their own tokens, added to your CSS file on install: `--calendar-sidebar`, `--calendar-sidebar-foreground`, `--calendar-sidebar-muted-foreground`, `--calendar-sidebar-primary` and the rest of shadcn/ui's sidebar set, each with a `calendar-` prefix. Inside the sidebar they replace your `--sidebar-*` tokens, so the rest of your app keeps its own sidebar theme. Change them in your CSS to restyle both sidebars.

## Features

- The mini calendar shows the month of the days on screen, highlights them, and marks today. Browse months with its arrows; the next navigation brings it back.
- Picking a day goes to its period in the current view: the day in day view, its week in week view.
- Scheduling starts marking the times you're free, like <Kbd>S</Kbd>, and leaves again on a second click. On phones the sheet closes so you can mark on the grid.
- "Meet with..." adds people from your contacts; the ones you meet with and the teammates shown are listed under it, each removable.
- Calendars are grouped by account, each account collapsible. Hover a calendar to show or hide it.
- The theme toggle cycles system, light and dark.
- On phones, the sheet closes on an outside tap, <Kbd>Esc</Kbd>, its close button (where the header's toggle sits) or a day pick.

## Mini Calendar

<ComponentPreview name="mini-calendar-demo" height={420} />

Mini Calendar is the small month at the top of the Calendar Sidebar, modeled on Notion Calendar's: week numbers down the side (`showWeekNumber={false}` hides them; Calendar Sidebar shows them while the provider's week numbers are on), today in red, and the days the calendar shows highlighted as one band. Browse months with the up and down arrows; away from today's month, the month's name shows with a button back to today.

It's built on [React DayPicker](https://daypicker.dev) directly, with its own styles, so it looks the same whatever your shadcn/ui `Calendar` and `Button` look like.

<InstallTabs item="mini-calendar" />

```tsx
import { MiniCalendar } from "@/components/mini-calendar";

export function DatePicker() {
  const [date, setDate] = React.useState<Date>();

  return <MiniCalendar currentDate={date} onDateSelect={setDate} />;
}
```

To follow a calendar, pass the days it shows as `visibleDays`: they're highlighted, and the mini calendar shows the month of the last one, so a week that crosses into a new month shows the new month. Calendar Sidebar does this from `useCalendar()`:

```tsx
const { view, currentDate, visibleDays, weekStartsOn, goToDate } =
  useCalendar();

<MiniCalendar
  currentDate={currentDate}
  visibleDays={view === "month" || view === "agenda" ? [] : visibleDays}
  weekStartsOn={weekStartsOn}
  onDateSelect={goToDate}
/>;
```

When `currentDate` or `visibleDays` change, the mini calendar goes back to their month, even after the arrows browsed away.

- Today is marked in your theme's primary color. The page renders with no today marked, then marks it in the browser, so server and client markup match.
- "Go back to today" shows once you browse to another month. It shows today's month and calls `onDateSelect` with today.
- Every day is a click target from edge to edge, with no gaps between days. Arrow keys move between days; the focused day gets a ring.
- Six weeks always show, so the height never changes between months.

## Calendar List

<ComponentPreview name="calendar-list-demo" height={460} />

Calendar List is the list of calendars in the Calendar Sidebar. Calendars are grouped under their account's email, each account collapsible, each calendar with its color. Hover a calendar to show its eye button and hide it; a subscribed calendar, like a holidays feed, gets a feed icon.

<InstallTabs item="calendar-list" />

The list lists the `calendars` of the surrounding [`CalendarProvider`](/docs/components/calendar-core), the same ones the event details' calendar picker offers. It's built from shadcn/ui's sidebar parts, so it needs a `SidebarProvider` around it.

```tsx
import { CalendarList } from "@/components/calendar-list";
import type { CalendarInfo } from "@/components/calendar-types";

const calendars: CalendarInfo[] = [
  {
    id: "personal",
    name: "Personal",
    color: "purple",
    email: "you@example.com",
  },
  {
    id: "holidays",
    name: "Holidays",
    color: "green",
    email: "you@example.com",
    isSubscribed: true,
  },
  { id: "work", name: "Work", color: "blue", email: "you@work.example.com" },
];

<CalendarProvider defaultEvents={events} calendars={calendars}>
  <SidebarProvider>
    <CalendarList />
  </SidebarProvider>
</CalendarProvider>;
```

Outside a provider, pass `calendars` yourself. Hiding a calendar only dims its row: read the hidden ids with `onHiddenCalendarIdsChange` to filter your events, or set them with `hiddenCalendarIds`.

```tsx
const [hidden, setHidden] = React.useState<string[]>([]);

<CalendarList
  calendars={calendars}
  hiddenCalendarIds={hidden}
  onHiddenCalendarIdsChange={setHidden}
/>;
```

### The provider's calendars, some hidden at first

Inside a `CalendarProvider` the list needs no `calendars` prop, and `defaultHiddenCalendarIds` starts it with calendars hidden. To take a hidden calendar's events off the views, see [Hide a calendar's events](#hide-a-calendars-events).

## Theme Toggle

<ComponentPreview name="theme-toggle-demo" height={240} />

Theme Toggle is the button at the bottom of the Calendar Sidebar. Each click moves to the next theme: system, light, dark, then system again. Its icon shows the current one: a monitor, a sun or a moon.

<InstallTabs item="theme-toggle" />

It installs `ThemeProvider` too, a client wrapper around [next-themes](https://github.com/pacocoursey/next-themes)' provider.

Wrap your app in `ThemeProvider`, in the root layout. With `attribute="class"`, dark mode sets the `dark` class that shadcn/ui's dark tokens use:

```tsx title="app/layout.tsx"
import { ThemeProvider } from "@/components/theme-provider";

export default function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <html lang="en" suppressHydrationWarning>
      <body>
        <ThemeProvider
          attribute="class"
          defaultTheme="system"
          enableSystem
          disableTransitionOnChange
        >
          {children}
        </ThemeProvider>
      </body>
    </html>
  );
}
```

Then render the toggle anywhere inside it:

```tsx
import { ThemeToggle } from "@/components/theme-toggle";

<ThemeToggle />;
```

If your app already has a next-themes provider, keep yours: the toggle only needs `useTheme()`.

- Server rendering shows the system icon until the page loads in the browser, where the stored theme is known, so the markup always matches.
- It forwards its ref and props to the button, so it works as a tooltip trigger: the Calendar Sidebar wraps it in a tooltip.

### In a tooltip

The toggle forwards its ref and props to its button, so it works as a tooltip's trigger.

<ComponentPreview name="theme-toggle-tooltip-demo" height={240} />

### ThemeToggle

Takes the props of a `<button>`. It's a ghost icon button, `size-7`, in the muted text color; `className` changes it.

### ThemeProvider

Takes next-themes' `ThemeProvider` props, such as `attribute`, `defaultTheme`, `enableSystem` and `storageKey`.

## Sidebar Overlay

<ComponentPreview name="sidebar-overlay-demo" height={240} />

Sidebar Overlay shows a sidebar's content as a modal sheet from the left or the right. The Calendar Sidebar and the [Details Sidebar](/docs/components/details-sidebar) use it on phones. It's the same sheet as shadcn/ui's `Sidebar` on mobile, but you own its open state and the breakpoint, so a sidebar can turn into an overlay at any width.

<InstallTabs item="sidebar-overlay" />

It also adds the sidebars' color tokens to your CSS: see [Colors](#colors).

```tsx
import { SidebarOverlay } from "@/components/sidebar-overlay";

export function MobileNav() {
  const [open, setOpen] = React.useState(false);

  return (
    <>
      <Button onClick={() => setOpen(true)}>Menu</Button>
      <SidebarOverlay
        open={open}
        onOpenChange={setOpen}
        side="left"
        title="Navigation"
        description="Pages of the app."
        style={{ "--sidebar-width": "15rem" } as React.CSSProperties}
      >
        <nav>{/* ... */}</nav>
      </SidebarOverlay>
    </>
  );
}
```

The sheet is as wide as `--sidebar-width`, up to 85% of the screen. Its title and description are for screen readers only.

- Closes on an outside tap and <Kbd>Esc</Kbd>, with focus kept inside while it's open.
- Opening focuses the sheet itself, not its first field, so a search field doesn't pop up a phone's keyboard.
- Works with shadcn/ui on Radix and on Base UI.
