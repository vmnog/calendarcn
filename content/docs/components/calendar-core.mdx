Calendar Core has no UI of its own. `CalendarProvider` holds the calendar's state (events, view, date, selection) and its settings, and `useCalendar()` reads and changes that state from any component inside it. Every view and the event details build on it. In the preview, the list on the right is the app's own `events` state: drag, resize or create an event and it updates.

## Installation

<InstallTabs item="calendar-core" />

## Usage

```tsx
import { CalendarProvider, useCalendar } from "@/components/calendar-provider";
import { WeekView } from "@/components/week-view";

export function Schedule() {
  return (
    <CalendarProvider defaultEvents={events}>
      <Toolbar />
      <WeekView />
    </CalendarProvider>
  );
}

function Toolbar() {
  const { monthName, year, goToPrev, goToNext } = useCalendar();
  // ...
}
```

### Controlled or uncontrolled

Each piece of state comes in a shadcn/Radix-style pair. Pass `defaultEvents` (or nothing) and the provider owns the events. Pass `events` with `onEventsChange` and your app owns them: the provider draws whatever `events` holds and reports every drag, resize, create and edit as the full next list. `view`, `date` and `numberOfDays` work the same way.

```tsx
const [events, setEvents] = React.useState(initialEvents);

<CalendarProvider events={events} onEventsChange={setEvents}>
  <WeekView />
</CalendarProvider>;
```

Use `onEventCreate`, `onEventUpdate` and `onEventSelect` to react to one change at a time, for example to save it to a server. `onEventCreate` also gets the occurrence copies the details' series arrows add, so a repeating event's next occurrence is saved like a clicked-in event. To fetch events for the dates on screen as people navigate, use `onVisibleRangeChange` and `loading`: see [Loading Events](/docs/loading-events).

### Server rendering

Without `date` or `defaultDate`, the calendar starts on today's period. The server doesn't know the viewer's today or time zone, so in that case the provider renders nothing until hydration finishes, and server and client markup always match. Pass `defaultDate` to render on the server.

## Configuration

<ComponentPreview name="config-demo" />

Display and interaction settings are plain props: a 24-hour clock, a [date-fns locale](https://date-fns.org/docs/I18n) for day and month names, the first day of the week, the visible hours of the time grid, and the minute step that drag, resize and click-to-create snap to. Events outside the visible hours are clipped at the edge, and hidden when they lie fully outside. Read the resolved settings anywhere with `useCalendarConfig()`, for example to format times in a custom renderer the way the calendar does.

## Custom event content

<ComponentPreview name="custom-event-content-demo" />

`renderEventContent` replaces what's drawn inside each event. The calendar keeps drawing the box (position, color, selection, drag and resize handles), so the renderer only returns the inside. `placement` says where the event is drawn and how much room it has: a timed block in the hour grid (`"time-grid"`, as tall as the event), a 24px bar in the all-day row (`"all-day"`), a 20px line in month view (`"month-item"` and `"month-bar"`), or a row as wide as the [agenda](/docs/components/agenda-view) (`"agenda"`). `isCompact` is true wherever there's room for one line only.

To replace the details popover instead, see [Event Details](/docs/components/event-details#custom-details).

## Typed events

<ComponentPreview name="typed-events-demo" />

Extend `CalendarEvent` with your own fields and pass your events in. The provider infers your type, and every callback and renderer gets it back. Read it in your own components with `useCalendar<Meeting>()`.

Once your type has required fields, `createEvent` becomes required: the calendar can't fill `room` or `attendees` for an event created by clicking an empty slot, so TypeScript asks you to.

```tsx
interface Meeting extends CalendarEvent {
  room: string;
  attendees: string[];
}

<CalendarProvider
  defaultEvents={meetings}
  createEvent={(range) => ({
    id: crypto.randomUUID(),
    title: "New meeting",
    ...range,
    room: "Atlas",
    attendees: [],
  })}
>
  <WeekView />
</CalendarProvider>;
```
