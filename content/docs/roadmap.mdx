CalendarCN is built in the open. This page lists the planned work, roughly in priority order. Plans change as people use the calendar, so treat it as a direction rather than a promise.

## Up next

### List in the shadcn registry directory

Submit CalendarCN to the shadcn/ui registry directory, so it shows up next to the other community registries and installs under the `@calendarcn` namespace.

## Later

Not scheduled yet, roughly in priority order.

- **Time zones**: a `timeZone` prop, and a second time zone column next to the time axis.
- **Recurring events**: expand recurrence rules into events, and edit "this event", "this and following events" or "all events".
- **More views**: a year view, and a resource view with people or rooms side by side.
- **Large calendars**: virtualized rendering for thousands of events.
- **Theming**: event colors as CSS variables, so you can add your own next to the seven built in, and shading for business hours.
- **Right-to-left** layouts.
- **More blocks**: more ready-made layouts next to [Calendar App](/docs/components/calendar-app), in the style of the shadcn/ui sidebar blocks.

## Recently shipped

The highlights. The [Changelog](/docs/changelog) lists every change item by item, with breaking changes called out.

- **The live demo as a block**: [Calendar App](/docs/components/calendar-app) installs the whole live demo with one command: both sidebars, the header, every view, the command menu, theme switching and .ics files. The live demo renders this block, so the two stay the same. Each part installs on its own too, from the [Calendar Sidebar](/docs/components/calendar-sidebar) and [Details Sidebar](/docs/components/details-sidebar) to the [Command Menu](/docs/components/command-menu) and the [Sample Data](/docs/sample-data).
- **Notion-style event details**: the details panel matches Notion Calendar section by section: time and date, time zone, repeat, participants and rooms, conferencing, location, links and attachments, description, calendar, availability and reminders. It works the same in Radix and Base UI projects, and each section can be used on its own. See [Event Details](/docs/components/event-details).
- **Base UI styles**: the registry installs into shadcn/ui projects set up with Base UI as well as Radix. The event details render their own popover, so they no longer rely on Radix-only features. See [Installation](/docs/installation). <Contributor handle="doneumark" pr={43} />
- **Import and export**: `parseIcs()` and `toIcs()` read and write .ics files from Google Calendar, Apple Calendar and Outlook, and a recipe syncs with the Google Calendar API. See [Import and Export](/docs/import-export).
- **Agenda view**: [Agenda View](/docs/components/agenda-view) lists the next 30 days' events by day, which suits phones better than a time grid.
- **Loading data by range**: `onVisibleRangeChange` reports the dates on screen as people navigate, so you can fetch events for them, and `loading` shows a progress bar while they arrive. See [Loading Events](/docs/loading-events).

The groundwork that turned the demo into a library:

- **Install with the shadcn CLI**: the calendar ships as shadcn registry items, from the full [Calendar](/docs/components/calendar) block down to [Calendar Core](/docs/components/calendar-core). See [Installation](/docs/installation).
- **Shared state**: `CalendarProvider` and `useCalendar()` hold events, the view, the date and the selection, so views no longer depend on the demo page. See [Calendar Core](/docs/components/calendar-core).
- **Standalone views**: [Day View](/docs/components/day-view), [Week View](/docs/components/week-view), [Month View](/docs/components/month-view) and [Time Grid](/docs/components/time-grid) each work with only a provider around them.
- **Your own event type**: views are typed with your event type, and render slots let you draw event content and details yourself.
- **Configuration**: snap interval, visible hours, 12 or 24 hour clock, a date-fns locale, week start, calendars, and the hour the grid opens on.
- **Touch**: drag, resize and create work on phones and tablets. Long-press to start, so a normal swipe still scrolls.
- **Accessibility**: every event has a descriptive label, <KbdGroup><Kbd>Alt</Kbd><Kbd>↑</Kbd></KbdGroup> and the other arrows move the focused event, adding <Kbd>Shift</Kbd> resizes it, and time changes are announced to screen readers.
- **Tests**: an end-to-end suite covers drag, resize, create, navigation and views on every pull request.
