title: Installation
description: Add CalendarCN to your project with the shadcn CLI.
---

In a project that has [shadcn/ui](https://ui.shadcn.com/docs/installation), one command adds the full calendar:

```npm
npx shadcn@latest add @calendarcn/calendar
```

The CLI copies the files into your components, hooks and lib folders, installs their npm dependencies and the shadcn/ui components they use, and adds the calendar's color tokens to your CSS file. Then [render it](#render-it). New to shadcn/ui, or want only some of the pieces? Follow the [steps](#step-by-step) below.

<Callout title="No registry to add">
  The CLI finds `@calendarcn` in shadcn's [registry directory](https://ui.shadcn.com/docs/registry/registry-index) and writes it under `registries` in your `components.json` during the first `add`. Add it yourself in three cases: with a shadcn CLI older than 3.7.0, which can't read the directory, before the first `add` if you use the [shadcn MCP server](/docs/ai#shadcn-mcp-server), which only knows the registries in `components.json`, and to [stay on a version](#stay-on-a-version), with that version's address. `npx shadcn@latest registry add @calendarcn` writes the same entry:

```json title="components.json"
{
  "registries": {
    "@calendarcn": "https://calendarcn.xyz/r/{name}.json"
  }
}
```

</Callout>

## Requirements

|                       | What CalendarCN needs                                                                                                                                                                                                                                                                                                                             |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Tailwind CSS**      | 4. The calendar's CSS uses `@utility`, which Tailwind CSS 3 doesn't have.                                                                                                                                                                                                                                                                         |
| **React**             | 19. React 18 isn't supported: the calendar renders and drags there, but its files fail the type check, and React 18 ignores the `inert` attribute that keeps the days off screen out of the tab order.                                                                                                                                            |
| **Framework**         | Next.js or Vite. No file imports from `next`, so the other frameworks shadcn/ui sets up (TanStack Start, React Router, Astro, Laravel) should work, but they aren't tested.                                                                                                                                                                       |
| **shadcn/ui**         | Base UI or Radix. Both are tested on every pull request.                                                                                                                                                                                                                                                                                          |
| **shadcn CLI**        | 3.7.0 or newer finds the registry by itself, and `npx shadcn@latest` always is. With an older one, add the `registries` entry above first.                                                                                                                                                                                                        |
| **TypeScript**        | `strict` passes. `noUncheckedIndexedAccess` doesn't: turn it off for the project the calendar's files are in.                                                                                                                                                                                                                                     |
| **Monorepo**          | Works with shadcn's [monorepo](https://ui.shadcn.com/docs/monorepo) template. Run `add` in the app (`apps/web`): the calendar's files go to the app, and the shadcn/ui components and the color tokens to `packages/ui`. The template turns on `noUncheckedIndexedAccess`, so set it to `false` in the app's `tsconfig.json`. See the note below. |
| **Server components** | The calendar's components are client components (`"use client"`), so they work in a Next.js App Router project. The calendar draws in the browser only: see [Server rendering](/docs/components/calendar-core#server-rendering).                                                                                                                  |
| **react-day-picker**  | 9 or 10, installed for you. The full calendar gets 10, the version the shadcn/ui `calendar` component asks for. Adding `year-view` or `mini-calendar` by itself installs 9, also over a 10 that's already there. Both work.                                                                                                                       |

Checked on November 17, 2026 by installing `@calendarcn/calendar` with shadcn 4.23.0 into new projects, then type-checking, building and dragging an event in each: Next.js 16.4 on Base UI and on Radix, Vite 8, and the monorepo template, all with React 19.3 and Tailwind CSS 4.3.

In a monorepo, the CLI adds the npm packages (`date-fns`, `@floating-ui/react-dom`, `react-day-picker` and `cmdk`) to `packages/ui/package.json`, while the calendar's files that import them are in the app. npm workspaces resolve them from the root. If your package manager doesn't, add `date-fns` and `@floating-ui/react-dom` to the app's `package.json` too.

## Step by step

<Steps>
<Step>

### Set up shadcn/ui

CalendarCN builds on shadcn/ui and Tailwind CSS 4. It works with both component libraries shadcn/ui offers, Base UI and Radix. In a new project, pick either one when you set up shadcn/ui:

```npm
npx shadcn@latest init -b base
```

Use `-b radix` for Radix instead.

Projects already on a Radix style (`new-york`, `radix-nova` and the other `radix-*` presets) or a Base UI style (`base-nova` and the other `base-*` presets) are ready. See the [shadcn/ui installation guide](https://ui.shadcn.com/docs/installation) for frameworks other than Next.js.

</Step>
<Step>

### Add components

Add the full calendar with the command at the top of this page. Or the whole [live demo](/), sidebars and command menu included:

```npm
npx shadcn@latest add @calendarcn/calendar-app
```

Or only the pieces you need, like the week view:

```npm
npx shadcn@latest add @calendarcn/week-view
```

[Registry items](#registry-items) lists them all.

</Step>
<Step>

### Render it

```tsx title="app/calendar/page.tsx"
"use client";

import * as React from "react";

import { Calendar } from "@/components/calendar";
import type { CalendarEvent } from "@/components/calendar-types";

export default function CalendarPage() {
  const [events, setEvents] = React.useState<CalendarEvent[]>([]);

  React.useEffect(() => {
    // Load your events here, e.g. from your API
    setEvents([
      {
        id: "1",
        title: "Team standup",
        start: new Date(2026, 10, 2, 9, 0),
        end: new Date(2026, 10, 2, 9, 30),
        color: "blue",
      },
    ]);
  }, []);

  return (
    <div className="h-screen">
      <Calendar events={events} onEventsChange={setEvents} />
    </div>
  );
}
```

The calendar fills its parent's height, so give the parent one. It renders in the browser only, since "today" and the time zone belong to the viewer.

</Step>
</Steps>

<Callout title="The D key in a new shadcn/ui project">
  The projects `shadcn init` creates come with a `ThemeProvider`
  (`components/theme-provider.tsx`) that switches between light and dark when
  you press <Kbd>D</Kbd>. <Kbd>D</Kbd> is also the calendar's day view shortcut,
  so one press does both. Remove `<ThemeHotkey />` from that file, or [change
  the calendar's
  shortcuts](/docs/keyboard-shortcuts#use-them-in-your-own-calendar).
</Callout>

<Callout title="Next.js Cache Components">
  With `cacheComponents: true` in your `next.config.ts` (a new project doesn't
  set it), `new Date()` can't run while a page prerenders. Create date-based
  events in an effect or an event handler, or load them from your API, as above.
</Callout>

## Updating

There's no package to upgrade. The registry at `calendarcn.xyz/r` serves the latest `main`, so every fix and improvement is live there as soon as its pull request merges, without waiting for a release. The [Changelog](/docs/changelog) lists what changed in each item and calls out breaking changes, and [Versions](#versions) covers the releases and how to stay on one.

To update, run `add` again for the items you installed. Each item updates the items it builds on, so `@calendarcn/calendar` updates all of them.

<Steps>
<Step>

### Preview the changes

`--dry-run` writes nothing. It lists every file the update would create, the files that changed and would be overwritten, and the identical files it skips, plus any new npm dependencies and CSS variables:

```npm
npx shadcn@latest add @calendarcn/calendar --dry-run
```

To see what changed in one of the files marked overwrite, pass its path as the list shows it:

```npm
npx shadcn@latest add @calendarcn/calendar --diff components/calendar.tsx
```

Without a path, `--diff` only shows the first five files.

</Step>
<Step>

### Commit, then overwrite

Commit your work first, so the update lands as a diff you can review and undo. Then run `add` with `--overwrite`:

```npm
npx shadcn@latest add @calendarcn/calendar --overwrite
```

It replaces the files that changed, creates the new ones, and installs any new npm dependencies and shadcn/ui components. Without `--overwrite`, the CLI stops to ask about each file that changed.

</Step>
<Step>

### Review and reapply your edits

```bash
git diff
```

Your own edits to the copied files show up as removed lines, since the update replaced them. Put them back by hand. When a hunk holds only your edit, `git checkout -p` restores it:

```bash
git checkout -p -- components/calendar.tsx
```

Then type-check and try your app before you commit the update.

</Step>
</Steps>

<Callout title="Customize with props to keep updates clean">
  Every copied file you edit is one you merge by hand on each update. Reach for
  props first: the [settings](/docs/components/calendar-core#configuration),
  `renderEventContent` and `renderEventDetails`, or your own components built on
  `useCalendar()`. `add` only writes the registry's files and the color tokens
  in your CSS file, so code in your own files is never overwritten.
</Callout>

## Versions

A release names a point on `main`: a tag such as `v0.1.0`, with a [GitHub release](https://github.com/vmnog/calendarcn/releases) that holds that version's section of the [Changelog](/docs/changelog). The whole registry shares one version, since the items build on each other. Watch the repository's releases on GitHub to hear about a new one.

Versions follow semver over what your code builds on: the exported components, hooks, functions and types, their props and fields, the file paths the items install, and the CSS variables. While CalendarCN is on 0.x, a breaking change raises the minor version (0.1.0 to 0.2.0) and anything else the patch (0.1.0 to 0.1.1). Each breaking change is marked **Breaking** in the Changelog, with what to change.

### Stay on a version

`@calendarcn` follows the latest `main` unless you say otherwise. To stay on a release, point the registry at its tag in your `components.json`:

```json title="components.json"
{
  "registries": {
    "@calendarcn": "https://raw.githubusercontent.com/vmnog/calendarcn/v0.1.0/public/r/{name}.json"
  }
}
```

Every `add` then installs that version, for the item and everything it builds on, since they all resolve through this one address. `--dry-run` shows what it would install:

```npm
npx shadcn@latest add @calendarcn/calendar --dry-run
```

GitHub serves these files from the repository at that tag. A version stays as it was released: fixes go into the next one.

### Move to the next version

Read the [Changelog](/docs/changelog) from your version up, change the tag in the address, then [update](#updating) as above: preview, overwrite, review. To follow the latest again, put back `https://calendarcn.xyz/r/{name}.json`.
